## 一、`INT` 改到 PC12 —— 可以用，但有一条 EXTI 约束要记住

```
INT ; R19.1 U1.54 U24.1        U1.54 = PC12 ✅，R19 = 10 kΩ 上拉到 3V3 ✅
```

**PC12 本身是个很干净的脚**（按 datasheet Table 12 核实）：

| 项 | 结论 |
|---|---|
| 脚号 | 54 ✅ |
| IO 类型 | **FT**（5 V 容忍，纯数字） —— 不像 PB12 是 `TT_a`（带模拟功能） |
| Additional functions | **无**（PB12 有 OPAMP4_VOUT / COMP7_INM） |
| 复用 | TIM5_CH2 / HRTIM1_EEV1 / TIM8_CH3N / UART5_TX / SPI3_MOSI / USART3_CK / UCPD1_FRSTX<br>—— 我们用的 USART3 只占 PC10/PC11（TX/RX），**不占 USART3_CK**，✅ 无冲突 |

### ⚠️ 但是：EXTI12 只能给一个脚用

STM32 的 EXTI 线按**引脚号**共享：`EXTI12` 同一时刻只能映射到
PA12 / **PB12** / **PC12** / PD12 / PE12 / PF12 中的**一个**。

```
PB12 = DC_OK        （光耦状态输入）
PC12 = INT          （TCA9539 中断）   ← 现在两者都想要 EXTI12
```

**不是硬冲突，但软件必须明确：`EXTI12` 给 `PC12`，`PB12` 只能轮询。**

这可以接受 —— `DC_OK` 是秒级变化的状态信号，10~100 ms 轮询完全够，
而且真丢了 DC 输出整板都断电了，中断也没意义。

> 如果将来想给四路光耦都上中断（EXTI11/12/13/14），那 `INT` 就得挪回
> **PC6 (38)** 或 **PC7 (39)** —— 那两个脚的 EXTI6/EXTI7 线上，
> PA6/PA7 是模拟（ADC 差分对，不配 EXTI）、PB6/PB7 未用，**完全没冲突**。
>
> **本轮按 PC12 记录，软件文档里写明"PB12 不配 EXTI"。**

## 二、🔴 FRAM（U10）还有两个脚是错的

```
U10.1 (A0)  ← 仍然悬空                                    ❌
U10.2 (A1) ┐
U10.3 (A2) ┴─ $3N163 ─ R25 (10 kΩ) ─ DGND                 ⚠️ 能用，但不必要
U10.7 (WP)  ← 接到了 `GND`（功率地！）                      ❌❌
```

### ❌ 错误 1：`WP` 接到了功率地 `GND`，应该是 `DGND`

```
GND ; R16.2 R20.2 R21.2 U4.1 U7.1 **U10.7** U14.1 U16.1 U19.1 U20.1 U23.1 U25.1 U26.1
      ↑ 这一串全是 36V/12V 端子和地桥，突然混进来一个 FRAM 的引脚
```

FRAM 整片都在 `DGND` 域（`U10.4 = VSS → DGND` ✅、`U10.8 = VDD → 3V3` ✅），
唯独 `WP` 拉到功率地。功能上因为星点最终连通可能"还能用"，但：

- `GND` 与 `DGND` 之间的任何电位差都直接加在 FRAM 的一个输入脚上
- **布局时这根线要从数字区横穿到 36 V 端子区** —— 一根完全没必要的天线，
  旁边就是 1.97 A（峰值 3.34 A）的母线回流

**改成 `DGND`。**

> **FM24V10 的 `pin 1` 是 `NC`（手册原文：not connected to the die），悬空完全正确。**
> 而且 FM24V10 **根本没有 `A0` 脚**，只有 `A2` (pin 3) / `A1` (pin 2) 两个地址脚。
> 我按通用 24Cxx 的三地址脚习惯去套，套错了。手册已入库：`reference/FM24V10-DataSheet.pdf`。
> 逐脚核定见 `docs/02-digital/CH340X与FM24V10-接法核定.md`。
>
> 下面这段原文保留作记录：

A1/A2 接了、A0 没接 —— **地址还是不确定的**。CMOS 输入悬空 = 随机，
表现是"有时候能读写、有时候 NACK"，是最难查的那类故障。

**三个地址脚要么都直接接 `DGND`，要么都经同一只电阻接 `DGND`，别混着来。**

### ⚠️ A1/A2 串 10 kΩ 到地：能用，但直接接地更好

CMOS 输入不吃电流，10 kΩ 上没有压降，逻辑上没问题。
但 10 kΩ 的阻抗比直连高，更容易耦合到噪声。**建议三个脚都直接接 `DGND`。**
（如果留 10 kΩ 是为了以后改地址，那就三个脚各留一只，并各留一个到 3V3 的空焊盘。）

### 🔴 而且这三个脚到底怎么接，必须查手册

> **1 Mbit 的 FRAM 通常要占用两个 I²C 从机地址**（16 位地址不够，
> 高位地址位借用 `A2` 脚的位置）。这种器件的 `A2` **不是地址脚**，接地会出错。
>
> **`FM24V10` 的手册仍然不在 `reference/` 里。这条不能猜。**

## 三、🔴 BOOT0 改了，但还是"不插跳线帽就悬空"

```
rev8:
  BOOT0   ; H2.2 U1.61                    ← BOOT0 直接到 3P 排针的中间脚
  $3N144  ; H2.3 R15.2   R15 = 10 kΩ → DGND
  $3N147  ; H2.1 R23.2   R23 =  1 kΩ → 3V3
```

**阻值选对了**（10 kΩ 下拉 / 1 kΩ 上拉，跳上拉时 BOOT0 = 3.3 × 10/11 = **3.0 V** ✅），
**但拓扑还是 3P 选择器 —— 两条路径都要靠跳线帽，不插就悬空。**

上一轮 P-14 的建议是：**下拉焊死，上拉才用跳线帽**。差别在这里：

| | rev8（3P 选择器） | 建议（固定下拉 + 临时上拉） |
|---|---|---|
| 不插跳线帽 | **BOOT0 悬空，启动模式不确定** ❌ | **BOOT0 = 0 V，正常启动** ✅ |
| 跳 2-3 | 正常启动 | — |
| 跳 1-2 / 插上 | 进 bootloader | 进 bootloader |
| 现场维修忘了插回去 | **变砖** | 正常工作，只是进不去 bootloader |

**改法（只动两根线）：**

```
BOOT0 (U1.61) ──┬──[ R15 10 kΩ ]── DGND          ← 直接连，不经过 H2
                │
                └──[ R23  1 kΩ ]── H2.1
                                   H2.2 ── 3V3    ← H2 改成 2P
```

## 四、USB-C + USB 转串口 —— 方向对，但有几个必须补的

新增 `USB1`（Type-C 16P）+ `U8`（MSOP-10）：

```
D+ ; U8.1 USB1.A6 USB1.B6          D- ; U8.2 USB1.A7 USB1.B7
TX1 ; U1.43 U8.9    ← PA9  = USART1_TX（MCU 输出）
RX1 ; U1.44 U8.8    ← PA10 = USART1_RX（MCU 输入）
3V3 ; … U8.7 …      DGND ; … U8.3 …      C32 100nF 去耦 ✅
R22 / R24 = 5.1 kΩ  ← USB1.B5 (CC2) / USB1.A5 (CC1) 到 DGND
```

**用一个 USB-C 同时做串口打印和串口下载，这个方向是对的**，比引一个 5P 排针好用。
下面是要补的。

### ✅ 先说对的：CC1 / CC2 的 5.1 kΩ 下拉

```
USB1.A5 (CC1) ─ R24 5.1 kΩ ─ DGND
USB1.B5 (CC2) ─ R22 5.1 kΩ ─ DGND
```

**这是 UFP（设备端）的标准 Rd 配置，两个 CC 各一只，取值正确 ✅。**
没有它，Type-C 对 Type-C 连接时主机根本检测不到设备。

### ✅ `VBUS` 没接 —— 这是对的，但要知道代价

`VBUS`（A4/B4/A9/B9）在网表里不出现，即**桥芯片完全由板上 3V3 供电**（自供电设备）。

**这是正确选择**，因为如果用 VBUS 给桥供电：板子没上电时，
桥的 TXD 会去驱动没供电的 MCU 的 PA10 → **通过 ESD 二极管给 MCU 倒灌供电**，
是典型的半上电损坏路径。

代价：**板子不上电时，插 USB 什么也读不到。** 调试时要记住先给仪器上电。

> 可选改进：`VBUS` 经两只电阻分压（比如 100 kΩ / 47 kΩ，5 V → 1.6 V）到一路空闲 GPIO，
> 做"USB 已连接"检测，软件据此决定要不要打开打印。**不是必须。**

### 🔴 缺 1：USB 的 ESD 保护

`D+` / `D−` 直接从连接器进芯片，**中间什么都没有**。
USB 口是整机最容易被 ESD 打的地方（用户天天插拔），而 DRS 自己的抗扰度是
ESD Level 3（8 kV air / 4 kV contact）—— **我们自己的对外接口不该比它差。**

**加一片 `USBLC6-2SC6`（SOT-23-6）或同类 ESD 阵列**，D+/D− 两路，
放在**紧贴连接器**的位置（在桥芯片之前）。这几乎是必装件。

### 🔴 缺 2：`U8` 十个脚只接了六个，4 / 5 / 6 / 10 全悬空

```
已接：1 (D+) · 2 (D−) · 3 (GND) · 7 (3V3) · 8 (→MCU RX) · 9 (←MCU TX)
悬空：4 · 5 · 6 · 10
```

**看封装（MSOP-10）、内置晶振、D+/D− 直连、这个脚位分布，U8 极可能是 `CH340E`。**
但网表里所有器件的 Value 都是 `{Value}` 占位符，**型号无法从网表确认**。

如果确实是 CH340E，下面两条是这颗芯片**最经典的两个坑**：

| # | 检查项 | 为什么要命 |
|---|---|---|
| 1 | **`V3` 脚**：VCC = 3.3 V 时 **V3 必须直接接到 VCC**；VCC = 5 V 时 V3 要对地接 0.1 µF | 接错或悬空 → **内部 3.3 V 电源建立不起来，芯片根本不工作**（表现为插上电脑完全不识别） |
| 2 | **TXD / RXD 的脚序** | 接反 = 两个输出对打，不但不通，还可能烧端口 |

> ⚠️ **`CH340E` 的手册不在 `reference/` 里，上面两条标「待核实」。**
> **请把 U8 的型号告诉我、并把手册放进 `reference/`**，我把 10 个脚逐个核完再给结论。
> 在此之前**不要出板** —— 这颗芯片接错，串口下载和打印两个功能一起没了。

### ~~⚠️ 缺 3：MSOP-10 的桥没有 DTR + RTS，自动下载做不了~~ → 🔧 **勘误：CH340X 做得了**

> CH340 手册 **5.3 节「DTR 与多模式 MCU 下载」**：CH340X 的 **6# 引脚外接 4.7 kΩ 下拉到 GND**，
> 就会进入**开源 DTR 增强模式**，6# 自动变成开源驱动的 `DTR#`，
> 手册原话「**用于连接 MCU 的 BOOT 模式引脚**」—— 默认被外部电阻保持低电平，
> 上位机可设其输出高电平。**这正是 BOOT0 要的，而且默认态就是安全的。**
>
> 用它可以把 `H2` 跳线帽整个省掉，见 `docs/02-digital/CH340X与FM24V10-接法核定.md` §1.3。
> ⚠️ 用了 DTR# 的 4.7 kΩ 就**必须删掉 `R15` 10 kΩ**，否则拉高只有 2.51 V，余量剩 0.20 V。
>
> 下面这段原文保留作记录：

10 个脚的桥芯片引不出完整的 `DTR` + `RTS`，
所以**没法做"一键下载"（上位机自动拉 BOOT0 + 复位）**。

这和之前写的操作流程一致，手动就手动：

```
1. 拔 H3（禁用看门狗，1.6 s 超时会打断下载）
2. 插 H2（BOOT0 拉高）
3. 按复位键 U22
4. 上位机串口下载
5. 拔 H2 → 按复位 → 插回 H3
```

> 想要一键下载就得换 **CH340C（SOP-16，有 DTR/RTS）** 或 CH343P 一类。
> **第一版手动完全可以接受**，这里只是让你知道选了 MSOP-10 就是选了手动。

### ⚠️ 缺 4：USB 外壳（USB1.13 / 14）直接接 `DGND`

```
DGND ; … USB1.13 USB1.14 USB1.A1B12 USB1.B1A12
        ↑ 13/14 是外壳/定位脚
```

**A1B12 / B1A12 是信号地，接 `DGND` 完全正确 ✅。
但把外壳也直接接 `DGND`，等于把 USB 线缆上的共模噪声和 ESD 直接灌进逻辑地** ——
而这块板上还有 1 LSB = 708 µV 的 AMC 采样链。

**建议（三选一，按机箱结构定）：**

| 方案 | 做法 |
|---|---|
| **A（最好）** | 连接器装在面板上，**外壳直接接机壳 PE**，不接 `DGND` |
| **B** | 外壳经 **1 MΩ ∥ 10 nF** 到 `DGND`（泄放静电但不形成地环路） |
| **C** | 保持直连，但**串一只 0Ω 留位**，实测 EMC 后再决定拆不拆 |

**至少改成 C**，别写死。

### ⚠️ 重申：PA9 / PA10 的 UCPD 副作用

datasheet Table 12 脚注 5：PA9 为高 → 激活 **PB6** 上 5.1 kΩ 的 UCPD 下拉；
PA10 为高 → 激活 **PB4** 上的。UART 空闲时两者都是高电平，所以**下拉常开**。

当前 PB4 / PB6 没用，不影响。**但软件初始化必须加 `PWR_CR3.UCPD1_DBDIS = 1`**，
否则将来谁拿 PB4 / PB6 去做输入会被一只看不见的 5.1 kΩ 坑到。
